# Lists of bugs found

## Priority
- On first load of the application, each subsequent page load shows a skeleton loading. Instead you should preload these pages. Data that is being fetched should show the skeleton, not the entire page. E.g. if a table is requesting data, the entire page should load except the table, then the table should show a skeleton to load the data. All pages should be fast and loaded as soon as the user switches to it. Performance between pages is pretty bad, loading for at a fraction of a second showing an empty or skeleton view. Improve this so it is seamless and fast.
- The tab bar for iOS is not fully at the bottom of the screen, it should also show a message icon in the middle as a circle but smaller than the rest. This will redirect to the new page for messages and announcements. Switching to another page should swipe the entire page as an animation. The user can also swipe left and right to switch pages which should replicate the tab bar function. Have the tab bar animate moving down and out of the screen view, this will used in some cases where the user is not on one of the main 5 tab screens. Or when scrolling down a long list. Also add the swiped left/right animation to all pages -> e.g. going to a sub settings page should swipe to the right (pages move to the left) while going back will swipe to the left (pages move right).
- The settings page is a little unorganized, freshen it up and make some better categories. 
- Buttons are not always functioning, sometimes or at some places, only the title of the button (button name) will make the button work or go to the next screen. Make this a requirement where clicking on the button's area / within outline should activate it. It should also have a hover option or change color when pressed.
- Notification system: Instead of banners, use a notification system (not push notifications) which will announce within the app. Replace the sync icon with the notification icon and a badge of notifications. This should show a sheet of notifications from three main categories: messages, matches/events, and system messages. Message notifications will contain notifications from messages like new messages or announcements. Matches/events will contain match, teams, scouting info etc notifications. And system notifications will be from the app. So like Sign-in again to sync changes -> should show here. Make it so you can dismiss, read, unread, and delete notifications (also options for mass delete, read, unread, etc). This should be on device only, settings for what is notified can be synced though. Also add a settings option for the settings. The notification settings in app settings can be moved here, and the previous notification settings can open the sheet -> notification settings automatically. This can also have a priority system: e.g. if login expiration is in a couple hours, this would have more importance
- Make sure to implement safe areas into the app. On iOS, the app extends into the control center and camera area. For example, the help glossary does not have the close button in view.
- Remove the current sync icon/notification This will be replaced with a smaller and robust system that will be explained and worked on later.
- Back system -> currently very buggy. For example, if I go to the scout tab, then to alliance selection -> Teams tab screen -> scout tab -> Then press the back button -> it goes to the teams screen. Back buttons should be entirely independent to their screens. So that means if I go back, it should only go back in history that is related to it's tab. So going back in settings far enough should only stay in the home page/screen. I would also recommend hiding the tab bar when in screens/pages that are different than the main tab screens. For example, going into alliance selection should hide the tab bar, forcing the user to go back a page to go to another tab. However, a different way can be resetting the screen to the default (scout page in this case) and when the user goes to the tab, it's not at alliance selection but at scouting screen. These are two way's I've thought of it but you suggest and choose what's best based on your knowledge and design guideline of apple and react best practices.
- Admin seed -> Allow the admin to seed the mock api with test data to play with for scouters and demoing the app. All data must be generated with data, or it can be retrieved from the api with api keys too. This can be at the middle of an event, e.g. in the middle of a couple qualifications to test all features.
- Help glossary tool tips: instead of automatically going to the help glossary after long pressing, instead show a tool tip of a summarized or cut off version of the definition which can be read more by a link or button that directs to the help glossary.
- When I reenter the app, it seems like the app does a full refresh and loads all components of the app on iOS. It seems to not be caching but please verify this because I am running this with npm run dev, which may not have that caching
- Add a thumbs down to reactions. Is there a way to see who reacted? Also delete the reaction and trash icon, this should not be apart of the message. When I hold down on a message, that's where actions should show: reactions, delete, etc. You may add three dots to the side of the message to do the same thing. The message ui is a little weird with the tab bar. If you implement hiding the tab bar away, this may not be an issue. When typing into the message box, it should expand if there are new lines (like a text area). Also instead of iOS zooming into the textbox, the app should automatically raise the message input box up, accommodating the native keyboard. I am not sure how this can be implemented, suggest what can happen.
- The mock api should be able to emulate most of the backend for testing, this would be a nice to have. But if too complicated you can leave it to simple things.
